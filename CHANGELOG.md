# Changelog

## 0.2.1 — 2026-09-05
- Scope lock covers Bash. Seen live on the first Sonnet 5 chunk build: the model rewrote `.claude/harness/chunks.json` through a Bash heredoc to add files to its own chunk (chunks 2 and 7), which the Edit/Write-only lock never saw. PreToolUse now also matches Bash: any command touching the plan file other than the harness CLI is denied; shell writes (`>`, `>>`, `tee`, `sed -i`, `cp`, `mv`) and scripted writes (`open(f, "w")`, `write_text`) to out-of-scope project files are denied; the Stop gate reports paths added to a chunk after activation as a scope change (`plan_modified`).
- No false positives from the new lock: arrows (`=>`, `->`), comparisons (`>=`) and heredoc bodies are not shell redirects (seen live: an Opus 5 Playwright smoke test was denied because `n => n.textContent` matched the redirect pattern); writes outside the project directory are not the plan's business.
- Ships the two post-0.2.0 gate fixes already described under 0.2.0 (latest acceptance run wins; hook feedback is not a new turn; `/chunk plan` passes the model's ID): they were committed after the v0.2.0 tag.
- Measured on four real builds of one spec (Sonnet 5 / Opus 5, with and without the plugin): `tests/REPORT.md` §6.10.

## 0.2.0 — 2026-09-05
- Research: `research/MODEL_MATRIX.md` (one cited row per current model: Fable 5.1/5, Opus 5, 4.8, 4.7, 4.6, 4.5, Sonnet 5, 4.6, 4.5, Haiku 4.5), 19 new official sources (S45–S63) and a 2026-09-05 re-fetch of every existing source with a provenance index; the hooks reference (S20) is now read in full.
- Profiles: seven tiers (`fable-5`, `opus-5`, `opus-4x`, `sonnet-5`, `sonnet-4x`, `haiku`, `generic`) plus a shared `_useful-output.md` block injected for every model. Lower tiers carry the cross-model self-check line Anthropic recommends for every model except Opus 5 [S8]; the Opus 5 profile still contains no verification instruction [S1].
- Detection: `claude-sonnet-5` → `sonnet-5`, `claude-sonnet-4-6` / `-4-5` → `sonnet-4x`, `claude-haiku-4-5` → `haiku` (previously all `generic`).
- API wrappers: per-model effort support ([S14]: Opus 4.5 supports effort; Opus 4.6 / Sonnet 4.6 have no `xhigh`; Sonnet 4.5 / Haiku 4.5 have none) and the exact sampling-parameter 400 list [S15]; the old code refused effort on Opus 4.5 and sampling on 4.6.
- Gate: per-tier defaults (`config.TIER_DEFAULTS`) and a grounding rule G7 (`gate.grounding`): a claim about an existing project file the model never opened this turn is sent back once with "read the file, then answer" [S8]; on by default on opus-4x, sonnet-5, sonnet-4x, haiku and generic, off on opus-5 [S1] and fable-5 [S28]. The Stop hook now detects the tier itself (no `model` field on Stop [S20]).
- Doctor: severity matrix per tier for R1–R17 (e.g. a "double-check" line is an error on Opus 5 and info on Sonnet/Haiku where Anthropic recommends a self-check [S8]); new R17 (effort level unsupported by the model in Claude Code [S28]); `--explain <rule>` and `--list-rules`; `--model` to pass the exact ID; R1 is auto-removed only on Opus 5; `--apply` preserves CRLF/LF line endings; fixtures for all seven tiers.
- Chunk mode: the `/chunk` skill passes the model's own ID to `chunk plan`, and the Stop gate caches a transcript-detected model so CLI calls made from the model's Bash tool know it (found live: a headless `/chunk plan` recorded `model: None` and gave every chunk the unknown-model default effort). `recommend_effort` takes the detected model; Claude Code's per-model effort table [S28] (no `xhigh` on Opus 4.6 / Sonnet 4.6, none on Haiku 4.5 / Sonnet 4.5 / Opus 4.5) and each tier's documented sweet spot [S14, S45, S4, S8]; `/chunk run` prints the exact `/effort` command or "effort: not supported on this model"; `chunk plan --model`.
- Gate fixes found on the first real builds: G6 judges the chunk's *latest* acceptance run (fail → fix → re-run green was blocked because any run in the turn had failed); Claude Code's "Stop hook feedback" user entry no longer starts a new turn, so evidence gathered before a format-only block still counts on the retry.
- Hooks: wrapper slimmed to one `timeout` + one Python (the old `cat`/`date`/`tr`/`cut`/`python -c` probes cost ~5 s per hook on Windows); Python logs `session_start` / `model_switch` / `stop` itself; inner timeout 12 s; hooks.json timeouts raised (SessionStart/PostModelSwitch 20 s, UserPromptSubmit/PreToolUse/PostToolUse 15 s, Stop 30 s); the `harness.doctor` import is lazy.
- Hooks: the Python CLI runs its own watchdog (`HARNESS_TIMEOUT`, default 12 s) for hook commands and exits 124 with no output when it fires — found by CI on macOS, which ships no `timeout(1)`, where a hung gate held the turn for the full 30 s.
- Installer: adds the marketplace by its full HTTPS URL (the `owner/repo` shorthand resolved to an SSH clone on a machine without a key); marketplace-add errors are printed instead of swallowed; `--selftest-only`.
- Fix: hook stdout/stdin are forced to UTF-8. On Windows a piped Python defaulted to cp1252, `print` of "≤"/"→" raised and the fail-open wrapper turned every hook into silent no-ops.
- Identity output is guarded against Claude Code's 10,000-character hook-output cap [S20].
- Fix (found live, `tests/REPORT.md` §6.6): resuming a session with a different `--model` carries no `model` field and fires no PostModelSwitch, so the transcript fallback re-injected the *previous* model as definitive. Now any identity that does not come from a hook field is worded as provisional and defers to the system prompt; a resume/fork without a model field drops the cached model; and transcript evidence newer than the cache wins.
- New `/harness-status` skill (`harness_cli.py status`): detected model + source + confidence, profile, gate state for this prompt, active chunk, last three log events, next step.
- Installer: post-install headless self-test (`claude -p --plugin-dir … --max-turns 1`) that must quote the MODEL IDENTITY line back; prints PASS/FAIL; `--no-selftest`.
- Tests: the two PATH-shim tests that build a fake bin dir from symlinks are skipped on Windows (they run in CI on Linux/macOS).
